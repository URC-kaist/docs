# 로버 검증과 운용 환경 전환 {#swhw-공동-검증과-릴리스}

[프로젝트 개요]({{< ref "docs/global-update-project/ko/_index.md" >}}) · [English]({{< ref "docs/global-update-project/en/acceptance.md" >}})

새 환경을 로버에 적용하기 전에는 SW·HW 담당자와 운용자가 함께 시험하고 결과를 검토합니다. SW는 코드·실행 환경과 소프트웨어 시험 결과를 준비합니다. HW 담당자는 실제 장비 구성과 시험 준비 상태를 확인하고, 운용자는 로버 사용 일정과 실제 시험을 조율합니다. 결과를 승인하고 전환을 결정할 사람은 팀이 정합니다. 인력 배정은 각 팀 리더가 맡습니다.

## 첫 릴리스에 필요한 기능부터 정하기 {#필요한-기능을-먼저-정합니다}

어떤 모드·센서·서비스 조합을 사용할지 정하고, 기능을 필수·후속 작업·실험으로 나눕니다. 화면에 placeholder가 있거나 스트림 설정이 있다는 이유만으로 모두 필수 기능에 넣지는 않습니다.

기능마다 현재 로버의 동작, 시험 시나리오, 기대 결과와 허용오차, 필요한 장비·참여자, 남길 결과를 기록하세요.

| 시험 분야 | 확인하고 남길 내용 |
| --- | --- |
| 환경 재현 | 클린 빌드와 설치 기록, 소스·의존성 버전, 다른 팀원의 재현 결과 |
| 제어와 Servo | 파라미터·인터페이스, lifecycle 상태 전환, 명령 모드, 단위·방향·제한값, 유효 시간이 지난 명령에 대한 반응, 제어권 전환 |
| 시뮬레이션과 자율 주행 | 모델 spawn, clock·센서, TF, 위치 추정·traversability, 필수 임무 경로, 실패·취소 동작 |
| 통신과 UI | 실제 ROS relay, 명령·상태 전달, 연결 해제·재연결, 사용할 운용 구성 |
| 카메라·추론·영상 | 필수 센서, 대상 장비에서 만든 모델 파일, NX 인코더, 합의한 동시 실행 부하 |
| 장치와 서비스 | 장치 준비 상태, 전원을 껐다 켠 뒤의 부팅, 재시작·재연결, 장시간 운용 |
| 로버 통합·필드 시험 | 필수 end-to-end 모드, 실제 움직임, 운용 절차, 복구 |

명령 유효 시간, 제어 주기, 지연, 정확도, 자원 사용량, 온도 등의 통과 기준은 임무 요구사항과 기존 로버의 측정값을 바탕으로 정합니다. 비슷한 부하 조건에서 비교하고, 모든 상황에 쓸 임의의 통과 수치를 만들지 않습니다.

## 장비별 시험 결과를 구분하기 {#환경별로-입증할-수-있는-범위}

개발자 PC에서는 해당 환경의 소프트웨어와 시뮬레이션 연동을 확인합니다. Nano에서는 실제 arm64/NVIDIA 환경과 연결 장치를 확인합니다. NX의 하드웨어 인코딩, 물리 인터페이스, 전체 운용 부하, 필드 동작은 실제 NX·캐리어 보드·로버에서 검증해야 합니다.

**PC나 Nano에서 통과한 결과를 NX 시험 통과로 기록하면 안 됩니다.** 환경마다 결과를 따로 남기고, 해당하지 않는 항목은 이유를 적으세요.

각 시험 기록에는 다음을 포함합니다.

- 소스·서브모듈 SHA, OS 이미지, BSP·커널, 런타임·의존성 버전
- 전력 모드, 입력 데이터와 설정, 실행한 명령
- 관측 결과, 시험한 사람, 시험 시각

## NX 시험 일정과 복구 준비 {#정비-시간과-복구}

개발 중에는 NX를 계속 운용할 수 있도록 유지합니다. 운용 중단이 필요한 시험 전에는 적용할 코드·이미지·설정, 관련 Nano 결과, 이번 시험의 목표, 실제 장비 구성, 중단 조건, 복구 절차, 참여자와 시간을 검토하세요. 부트 펌웨어 호환성도 복구 계획에 포함해야 합니다. SSD 복사만으로 복구할 수 있다고 가정하면 안 됩니다.

시험뿐 아니라 복구, 원인 분석, 재시험 시간도 확보합니다. 운용 환경 전환을 별도로 합의하지 않았다면 시험 후 기존 환경으로 복구하고 필수 기능을 확인하세요. Nano의 복구에 성공했어도 NX의 복구 절차는 NX에서 따로 확인해야 합니다. NX 사용 시간을 확보하지 못한 항목은 미완료로 남깁니다.

## 자료 공유, 구현 완료, 로버 전환은 별도 단계 {#서로-다른-세-가지-이정표}

1. **착수 자료 공유:** 프로젝트 목적과 방향, 리더가 결정할 사항, 처음 할 작업을 팀에 알립니다.
2. **구현 결과 검토:** 코드를 리뷰하고, 명시한 환경과 기능에 대한 시험 결과를 확인합니다.
3. **로버 운용 환경 전환:** 필수 NX·필드 시험을 마치고, 검증한 배포·복구 파일, 운용 준비, 작업 시간을 확보한 뒤 팀이 전환을 결정합니다.

이 자료를 공유했다고 로버 전환까지 끝난 것은 아닙니다. 시험, 수정, 재시험도 담당자와 시간을 배정해야 하는 프로젝트 작업입니다.
