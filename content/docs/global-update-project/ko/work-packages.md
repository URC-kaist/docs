# 결과와 근거를 단위로 업무를 나눕니다

[프로젝트 개요]({{< ref "docs/global-update-project/ko/_index.md" >}}) · [English]({{< ref "docs/global-update-project/en/work-packages.md" >}})

**SW 팀장 `@yongwhan-chung`이 담당자와 투입 여력을 정합니다.** 이 문서는 역할과 의존성을 제안합니다. 한 사람이 여러 역할을 맡을 수 있으며, 아래 표가 고정 인원수를 요청하는 것은 아닙니다. 요청자는 Yongwhan에게 사용 가능함이 확인된 Nano의 인수를 요청했습니다. 인수와 시험 준비의 완료 여부는 아직 보고되지 않았습니다.

| 분야 | 산출물 및 필요한 역량 | 의존성 / 병렬 작업 | URC 2027 준비에 대한 기여 |
| --- | --- | --- | --- |
| 플랫폼/빌드 | 클린 Humble/Jazzy 구성 절차, 버전 고정, CI, Nano 설정; Linux/Jetson/빌드 | 기준 환경 파악 및 Nano 인수부터 시작하며 다른 분야를 지원 | 재현 가능한 온보딩과 배포 |
| 내비게이션/시뮬레이션 | Jazzy Nav2/BT 설정, 위치 추정·주행 가능성 처리, Harmonic | 워크스테이션 시나리오는 네이티브 통합과 병렬 진행; 제어·센서 규약 합의 | 반복 가능한 자율 임무 리허설과 새 기능 평가 |
| 통신/UI | gateway/dashboard, 네이티브 ROS relay, 무선·proxy·서비스 | mock과 클린 웹 빌드는 독립 수행; 전체 프로파일은 통합 필요 | 신뢰할 수 있는 운용 제어와 상태 관측 |
| 매니퓰레이터/CAN/제어 | ros2_control, 구동·조향, MoveIt Servo, CAN 인터페이스 | mock·수명 주기 시험은 조기 시작; 물리 시험은 HW/운용 협업 필요 | 검증된 운동과 모드 전환 |
| 인지/영상 | 카메라 SDK/wrapper, 모델 생성 절차, 추론, GStreamer | Nano 구성 후 진행; NX 인코딩과 동시 부하는 별도 확인 | 재현 가능한 센싱과 운용 영상 |
| 시스템 인수/릴리스 | 공동 시험표, 운용 절차, 배포·복구 묶음 | 일찍 계획하고 물리 시험·재시험은 순차적으로 수행 | 통합 로버 준비 상태 확보 |

한 명의 통합 담당자가 공통 launch, 메시지, TF, URDF, 운용 프로파일, 플랫폼 버전을 조정합니다. 각 작업에는 책임 담당자와 검토자가 필요합니다. 리뷰와 HW/운용 참여 시간도 투입 여력에 포함합니다.

## 먼저 배정할 세 가지 작업

1. **기준과 범위:** 실제 운용 환경을 식별하고 SW, HW 통합, 로버 운용 담당자와 첫 릴리스의 필수 프로파일·기능을 합의합니다.
2. **Nano 시험 장비:** 인수·목록화하고, 접근과 엔드포인트 격리, 시험 장치, 구성·복구 절차를 준비합니다.
3. **재현성:** 클린 기준/후보 빌드 시도와 대표 네이티브 smoke 시나리오를 수행하고, 다른 팀원의 재현 및 근거를 확보합니다.

이 작업들은 겹쳐 진행할 수 있습니다. 결과를 통해 실제 의존성을 정리하고 분야별 포팅의 추정 근거를 얻습니다. 아직 병합되지 않은 배포 작업은 명시적으로 통합 여부를 결정해야 하며, 조사 브랜치에 이미 포함되었다고 가정하지 않습니다.

## 시간과 인력에 관해 확인할 정보

각 작업의 제안 담당자에게 주당 가용 시간, 직접 작업량의 범위, 추정 확신도, 선행 조건, 외부 대기 시간을 확인합니다. 구현 시간과 리뷰·장비 예약·부품·NX 정비 대기를 구분합니다. 첫 환경 구성·포팅 실습 후 추정을 갱신합니다.

실제 팀의 URC 2027 준비 완료 시점과 통합 리허설에서 역산해 계획합니다. 공동 시험, 진단, 수정, 재시험, 문서화, 복구 연습 시간을 확보합니다. 이 문서에서 대회 날짜, 납기, 인력 투입을 임의로 확정하지 않습니다.

## Codex에 맡길 수 있는 일

범위가 명확한 의존성 조사, 환경 구성 절차, 문서화된 API·설정 포팅, 의미 있는 시험, 빌드, 실패 분석, 작은 PR 초안 등을 맡길 수 있습니다. 소스 버전, 환경, 바꿀 인터페이스, 필요한 결과, 근거 위치를 지정합니다.

사람은 물리 구성과 보정값을 확인하고, 운동·장치 시험을 감독하며, 허용할 임무 동작을 결정하고 시스템 결과를 인수합니다. 빌드 성공으로 조향 방향, 실제 장애물 처리, 전체 부하에서의 신뢰성을 입증할 수는 없습니다.

## 업무 인계 형식

결과물, 이유, 선행 조건, 담당자·검토자, 소스·환경, 명령 또는 절차, 인수 근거, 복구·중단 조건을 기록합니다. 부재나 중단 전에는 마지막 결과, 브랜치/SHA, 남은 질문, 다음 행동을 남깁니다. 작은 종단 간 시나리오를 일찍 통합하여 최종 로버 시험 전에 분야 간 경계를 확인합니다.

작업을 맡을 때는 [개발 시작 카드]({{< ref "docs/global-update-project/ko/start.md" >}})를 사용하고, 범위가 명확한 마이그레이션 인계는 [컨트롤러 로딩 예제]({{< ref "docs/global-update-project/ko/controller-example.md" >}})를 참고합니다.
