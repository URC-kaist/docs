# 지도

[English]({{< ref "docs/2026_mr2/navigation/maps.md" >}})

*Codex의 도움으로 작성한 map-pipeline 문서입니다. 2026년 11월 25일에 갱신했으며, Jaeuk Kim이 2026년 3월에 작성한 설명과는 별개의 문서입니다.*

Translation: used [pianojay/mr2-translation-ko](https://github.com/pianojay/mr2-translation-ko), November 25, 2026.

자율 주행과 운용자 대시보드에는 서로 다른 종류의 지도가 필요합니다. 자율 주행 스택에는 경로 계획에 사용할 지형 비용이 필요하고, 대시보드에는 운용자가 장소를 알아볼 수 있는 RGB 영상이 필요합니다. 같은 지면을 다루더라도 두 지도의 픽셀, 투영법, 원점, 인코딩이 같을 필요는 없습니다.

현재 지도 생성 절차는 기존 `lidar` 실험을 대체한 [URC-kaist/map-pipeline](https://github.com/URC-kaist/map-pipeline)에서 관리합니다. 이 문서는 생성물을 자율 주행 및 시각화에 연결할 때 필요한 좌표 규약을 설명합니다. 세부 변환 명령과 원본 데이터 목록은 파이프라인 문서에서 관리합니다.

## 지도 이미지에는 좌표 규약이 필요합니다

PNG는 색이나 비용을 담은 배열입니다. 그 자체로는 픽셀이 지구상의 어디에 있는지 알 수 없습니다. 좌표 참조 체계(CRS), 픽셀 간격, 범위, 래스터와 로봇 좌표계의 관계가 필요합니다.

**Datum**은 좌표의 지리적 기준을 정의합니다. **투영법**은 지리적 위치를 평면에 나타냅니다. ROS의 **좌표계**(frame)는 자세를 표현하는 원점과 축을 정의합니다. 두 데이터에 같은 좌표계 이름을 붙인다고 datum이나 투영법이 변환되는 것은 아닙니다.

준비된 MDRS 구성에서는 다음 좌표계를 구분합니다.

| 데이터 또는 생성물 | 좌표 참조 체계 | 용도 |
| --- | --- | --- |
| 지표면 DEM과 기본 지형 격자 | NAD83(2011) / UTM zone 12N, EPSG:6341 | 미터 단위의 고도 및 경사도 처리 |
| 지형 기준점 좌표 | NAD83(2011) geographic, EPSG:6318 | 지형 CRS에서 선택한 국소 원점의 위치 지정 |
| 원본 RGB 영상 | NAD83 / UTM zone 12N, EPSG:26912 | 지리 좌표가 부여된 항공 영상 |
| 대시보드 타일 격자 | Web Mercator, EPSG:3857, 북쪽 원점의 XYZ | 표준 웹 지도 타일 주소 |
| 실행 중인 로봇 자세 | 실행 중인 위치 추정 변환을 거친 ROS `map` | 자율 주행 목표, 경로, 로봇 자세 |

EPSG:6341과 EPSG:26912는 모두 UTM zone 12N을 사용하지만 datum 정의가 다릅니다. 파이프라인은 실제 CRS에 따라 데이터를 변환합니다. 좌표를 그대로 두고 CRS 이름만 바꾸지 않습니다.

## 지형 격자와 국소 지도 원점

기본 지형 구성은 GeoTIFF에 투영 좌표를 유지합니다. 출력 범위는 동쪽 좌표 518000~522000 m, 북쪽 좌표 4248000~4253500 m입니다. 셀 간격은 0.5 m이며, 8000열 × 11000행, 즉 4 km × 5.5 km입니다.

이 확장 구성은 2018년, 2020년, 2022년 DEM을 결합합니다. 앞선 자료의 유효한 샘플은 유지하고, 데이터가 없는 곳만 뒤의 자료로 채웁니다. 일부 입력의 해상도는 1 m이므로 출력 격자를 0.5 m로 만든다고 원본의 세부 정보가 늘어나지는 않습니다. 파이프라인의 [범위 기록](https://github.com/URC-kaist/map-pipeline/blob/becb193b8067719e2cfe73acfd0aa54e5ee8b028/docs/EXPANDED-COVERAGE.md)은 URC 2027 준비를 위한 영역과 추가 북쪽 여유 범위를 설명합니다. 이는 2026년 3월에 작성한 다른 장의 맥락과 구분해야 합니다.

Nav2용 국소 좌표를 만들 때는 설정한 기준점을 같은 CRS로 투영한 다음, 그 위치를 뺍니다.

```text
local_x = projected_easting  - anchor_easting
local_y = projected_northing - anchor_northing
```

이 연산에는 회전이 없습니다. 기본 기준점은 대략 E=518000 m, N=4250500 m이며, 지도 왼쪽 아래의 국소 원점은 `[0, -2500, 0]` 부근입니다. 기준점이 출력 사각형의 중심에 있을 필요는 없습니다. 정확한 기준점, 크기, 원점은 이미지 파일명으로 추측하지 말고 생성된 메타데이터에서 확인하세요.

래스터 범위는 격자의 **바깥 경계**를 나타냅니다. 픽셀 중심은 경계에서 반 셀 안쪽에 있습니다. TIFF와 PNG의 행은 북쪽에서 남쪽으로 이어지며, Nav2 지도 로더는 점유 격자를 구성할 때 행 방향을 뒤집습니다. 생성된 YAML의 원점은 이미지 첫 픽셀의 중심이 아니라 왼쪽 아래 바깥 모서리입니다.

이미지를 자르거나 크기를 바꾸면 이 관계도 바뀝니다. 대응하는 YAML과 메타데이터를 함께 보관하고, 격자가 바뀔 때마다 원점과 해상도를 갱신하세요.

## 투영된 국소 좌표가 곧 ROS map 좌표는 아닙니다

UTM 기준점을 빼면 쓰기 편한 국소 격자가 생기지만, 그 격자가 정확한 동·북·상(ENU) 접평면이 되는 것은 아닙니다. 자오선 수렴각 때문에 UTM 격자의 북쪽과 지리적 북쪽이 다를 수 있습니다. 지리적 datum 선택도 중요합니다.

실행 중인 위치 추정 구성은 datum, 방향 규약, 좌표 변환으로 로봇의 `map` 좌표계를 정합니다. 생성한 지형 지도를 불러오기 전에 격자의 축과 원점이 이 좌표계에 어떻게 대응하는지 확인해야 합니다. 다른 좌표 가정이 이미 일치할 때만 평행 이동으로 충분합니다. 위도·경도 표기가 같다는 사실만으로는 이를 입증할 수 없습니다.

배포할 때는 다음을 함께 확인하세요.

1. Datum 정의를 포함한 원본과 출력의 수평 CRS
2. 설정한 지형 기준점과 실행 중인 위치 추정 datum
3. 자오선 수렴각, 방향 오프셋, 축 사이에 필요한 회전
4. 위치를 아는 기준 지점을 실행 중인 `map` 좌표계로 변환한 결과와 다시 지리 좌표로 되돌린 결과. 불러온 지도의 경계도 포함합니다.

파이프라인에는 과거 1 km 작업 흐름을 위한 WGS84 중심의 방위정거리도법(AEQD) 예제도 있습니다. AEQD도 하나의 투영법입니다. ENU라고 부르거나 과거에 자른 지도를 정확히 재현한 것으로 취급해서는 안 됩니다.

2022년 DEM 원본에는 NAVD88/Geoid18이 명시되어 있습니다. 반면 확인한 2018년과 2020년 원본 메타데이터만으로는 수직 datum을 확정할 수 없습니다. 원본 고도는 미터 단위를 그대로 유지하며 수직 datum 변환을 적용하지 않습니다. 겹치는 영역을 비교한 결과는 수치적 일관성을 뒷받침하지만, 수직 datum이 같거나 경사도 경계에 이음새가 없다는 보장은 아닙니다. 수평 재투영만으로 타원체 높이와 다른 높이 기준이 일치하지는 않습니다.

## 경사도 생성물과 Nav2 로딩 규약

지형 파이프라인은 Horn 미분 연산으로 DEM의 경사도를 계산합니다. 데이터가 없는 곳은 명시적으로 유지합니다. 바깥 테두리처럼 주변의 유효한 이웃 셀이 모두 갖춰지지 않은 셀은 평평한 지면처럼 처리하지 않고 미확인 상태로 남깁니다.

자율 주행 이미지는 **raw-mode** 값을 사용합니다. 경사도 비용은 0~100, 미확인 영역은 255입니다. 최대 비용에 해당하는 각도는 45도로 설정되어 있습니다. 이는 지형 비용의 인코딩이며, 비용이 더 낮은 모든 셀을 로버가 안전하게 통과한다고 검증한 결과는 아닙니다. 진단용 경사도 PNG와 높이 PNG는 별개의 생성물입니다.

`occupancy.png`는 함께 생성된 `map.yaml`로 불러오세요. 과거의 scale-mode YAML을 대신 사용하면 안 됩니다. 비용의 중간 단계를 유지하려면 Nav2 static layer의 `trinary_costmap` 설정도 확인하세요.

**실행 중인 로버와의 연동은 지도 생성과 별개의 작업입니다.** 기존 MR2 cropper는 scale-mode 설정과 과거 메타데이터 구조를 사용합니다. 새 raw-mode 이미지와 메타데이터를 그대로 끼워 넣을 수는 없습니다. 새 생성물을 실제 배포된 자율 주행 지도라고 설명하려면 먼저 자르기, 좌표 정합, 지도 로딩을 맞춰 수정하고 확인해야 합니다. 기존의 지도 밖 빈 지도 대체 기능은 좌표 정합을 입증하지도, 빠진 지형 사전 정보를 제공하지도 않습니다.

## 대시보드 RGB 타일과 지리 좌표 오버레이

RGB 파이프라인은 서로 인접한 NAIP 2024 영상 두 개를 모자이크하고, Web Mercator로 변환한 다음 DEM의 바깥 경계에 맞춰 자릅니다. 이 경계는 포함할 지리적 범위를 정한 것이지, 영상을 Nav2 국소 좌표로 인코딩하라는 뜻이 아닙니다. 자른 사각형 안에서도 RGB 데이터가 없는 영역은 투명하게 남습니다.

```text
RGB TIFF in EPSG:26912 ──> EPSG:3857 ──> XYZ tiles ──> MapLibre
DEM footprint in EPSG:6341 ──> transformed crop boundary

ROS map-frame pose ──> live /toLL ──> longitude/latitude ──> dashboard overlay
```

XYZ 주소에서 x는 동쪽으로 증가하고, y는 웹 지도 격자의 북쪽 경계에서 남쪽으로 증가합니다. 남쪽이 원점인 TMS 규약과 다릅니다. 준비된 타일은 256픽셀 PNG이며, 실제 파일이 있는 줌 단계는 14~18입니다. 제공 경로는 `/tiles/naip/{z}/{x}/{y}.png`입니다.

대시보드는 실행 중인 위치 추정 변환을 사용해 로봇의 `map` 자세를 지리 좌표로 바꿔야 합니다. 기존 지도 미리보기 코드는 `/toLL`을 호출합니다. 별도의 path-to-GeoPath 변환기는 설정된 UTM 변환으로 지리 좌표 경로를 제공합니다. 실행 중인 지리 좌표 변환을 하드코딩된 이미지 기준점 빼기로 대체하지 마세요.

새 타일 모음의 raster source에는 생성된 범위, XYZ 규약, 타일 크기 256, `maxzoom: 18`을 설정하세요. 기존 타일을 확대해 화면 줌은 22까지 올릴 수 있지만, 존재하지 않는 z19~22 파일을 요청해서는 안 됩니다. 원본 영상의 해상도는 0.6 m입니다. 확대하면 더 크게 보일 뿐 세부 정보가 추가되지는 않습니다. 준비된 뷰어는 픽셀 경계를 보여 주기 위해 nearest 방식의 래스터 샘플링을 사용합니다.

타일 요청은 개발용 프록시나 nginx 배포 구성을 통해 대시보드와 같은 origin의 생성된 타일 모음으로 전달되어야 합니다. 독립 뷰어가 동작한다는 것은 타일 생성물을 확인한 것입니다. 기존 대시보드에도 설정과 배포가 끝났다는 뜻은 아닙니다.

## 생성물 재현과 좌표 정합 확인

저장소의 지원 환경과 원본 다운로드 지침을 따르세요. map-pipeline 루트에서 실행할 순서는 다음과 같습니다.

```bash
/usr/bin/python3 download_sources.py
/usr/bin/python3 prepare_sources.py
/usr/bin/python3 mosaic_dem.py
/usr/bin/python3 Lidar-pipeline/pipeline.py --output Lidar-pipeline/output/mdrs-expanded
/usr/bin/python3 RGB-pipeline/generate.py
/usr/bin/python3 RGB-pipeline/serve.py
```

다시 생성할 때는 새 출력 디렉터리를 선택하세요. 원본 체크섬, 실제 실행한 설정, 투영 메타데이터, 출력 해시는 결과의 일부입니다. MapLibre 자산은 선택 사항인 그래픽 뷰어에만 필요하며, 타일 생성이나 제공에는 필요하지 않습니다.

릴리스 기록에는 새 checkout에서의 재생성, 네이티브 Nav2 라이브러리의 지형 지도 디코딩, 타일 배치 계산, 독립 뷰어 검증이 담겨 있습니다. 이 검사는 선택한 좌표 연산 안에서 재현성과 좌표 일관성을 확인한 것이며, 현장 좌표 정합을 입증하지는 않습니다. 문서화된 환경은 정밀한 변환 격자와 기준 시점(epoch) 보정을 검증하지 않은 근사 datum 변환을 사용합니다. 왕복 변환의 수치 오차가 아주 작다고 로버와 이미지 사이의 실제 위치 오차도 그 정도라는 뜻은 아닙니다. 현장에서 정합을 신뢰하기 전에 측량한 기준점이나 실행 중인 좌표 변환으로 확인하세요.
